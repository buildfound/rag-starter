# RAG Starter

A small, runnable retrieval-augmented generation starter built with Next.js, Postgres, pgvector, and OpenAI. Add Markdown or text files, ingest them, and ask questions through a streamed web interface with numbered source citations.

## Why this shape?

- **Postgres with pgvector:** application data and embeddings live in one familiar database, without a separate vector service.
- **Small chunks with overlap:** text is split near paragraph or word boundaries at roughly 1,200 characters, with about 200 characters of overlap to preserve nearby context.
- **Numbered citations:** retrieved chunks become sources `[1]`, `[2]`, and so on. The model is instructed to ground claims in those sources and say when the context is insufficient.
- **Streaming:** the answer is rendered as it arrives instead of waiting for the whole completion.
- **Few dependencies:** database access uses `pg`, model calls use the official `openai` package, and ingestion runs with `tsx`.

## Quick start

You need Node.js 20.9 or newer, Docker, and an OpenAI API key.

```bash
docker compose up -d
cp .env.example .env.local
npm install
npm run ingest -- ./docs
npm run dev
```

Add your API key to `.env.local` before ingestion, then open [http://localhost:3000](http://localhost:3000). The included `docs/` files make the first ingestion immediately usable.

The database schema is applied automatically when the Postgres volume is first created. To apply a changed schema to an existing volume, run the SQL manually or recreate the local volume if its data is disposable.

## Configuration

| Variable | Purpose | Default in `.env.example` |
| --- | --- | --- |
| `DATABASE_URL` | Postgres connection string | Local Docker database |
| `OPENAI_API_KEY` | OpenAI API key | Empty |
| `OPENAI_CHAT_MODEL` | Model used to write answers | `gpt-4o-mini` |
| `OPENAI_EMBEDDING_MODEL` | Model used for document and query vectors | `text-embedding-3-small` |

The schema fixes embeddings at 1,536 dimensions. If you change to a model or configuration with another size, update both `db/schema.sql` and the embedding request.

## Ingestion and chunking

```bash
npm run ingest -- ./path/to/documents
```

The script recursively reads `.md` and `.txt` files. `lib/chunk.ts` normalizes whitespace and creates chunks of up to 1,200 characters. It prefers paragraph breaks late in a chunk, falls back to a word boundary, and starts the next chunk about 200 characters before the split.

Embeddings are requested in batches of 100. Each file is stored as one document using its path as the unique source; re-ingesting that source updates its title and replaces all of its chunks in a transaction.

## How retrieval and citations work

For every question, `lib/retrieve.ts` creates a 1,536-dimensional query embedding and runs a cosine-distance search against the HNSW index. The five nearest chunks are numbered in retrieval order and placed in the chat prompt.

The prompt tells the chat model to answer only from that context, cite factual claims with source numbers such as `[1]`, and say it does not know when the supplied chunks are insufficient. Citations are generated by the model, so applications with stricter requirements should validate citation placement and whether each cited chunk supports the claim.

The `/api/chat` response body is a plain UTF-8 text stream. Before the body, it sends an `x-sources` header containing base64-encoded JSON:

```json
[
  {
    "number": 1,
    "source": "docs/how-it-works.md",
    "title": "How retrieval works",
    "similarity": 0.81
  }
]
```

The client decodes this header, detects citation markers in the streamed answer, and lists the matching source metadata below it.

## Adapt it

- Change chunk size and overlap in `scripts/ingest.ts` or pass options to `chunkText`.
- Adjust retrieval count in `app/api/chat/route.ts`.
- Add metadata columns and filters to the schema and retrieval query.
- Replace the file reader while keeping the document/chunk write path.
- Add authentication and rate limiting before exposing the endpoint publicly.
